**作成**: 2026-05-12 / **担当**: ふかみん  
**依頼元**: CEO  
**ステータス**: 計画案（PoC）

---

## 1. 課題の整理

旧アニメ作品はほぼ **4:3 アスペクト比（SD画質 720×480 以下）** で制作されている。これを現代の **16:9 4K（3840×2160）** モニタで違和感なく視聴できる形に変換したい。

技術的に解くべき問題は2つあり、それぞれ別物：

| 課題 | 内容 | 技術領域 |
|------|------|----------|
| ① 解像度向上 | SD → 4K（縦横 約4倍） | Super-Resolution |
| ② アス比拡張 | 4:3 → 16:9（横方向 +33%） | Outpainting / Image Completion |

それぞれ手法は確立されているが、**アニメ特有のセル画的タッチ・線画品質を保ったまま組み合わせる**部分が腕の見せ所。

---

## 2. 設計上の重要な判断

### 2-1. 「カスタムモデル」の定義

Mac M系チップ単体での生成モデルのフルスクラッチ学習は現実的でない（A100相当のVRAMが必要）。本PoCにおける「カスタム」は以下の意味で扱う：

- **独自パイプライン設計** — 既存事前学習モデルを目的に合わせて組み合わせ
- **シーン適応制御** — 後述の「シーン分類器」で手法を動的に切り替え（これがコア独自性）
- **軽量LoRA微調整** — 必要なら Stable Diffusion に対し対象作品の絵柄でLoRA学習（数百MB級、Mac M2/M3 で実行可能）

スクラッチ学習をやるならクラウドGPU（A100×n枚×数日）必須であり、まずPoCで方針を固めてから判断するのが妥当。

### 2-2. 比較する4手法

| # | 手法名 | アスペクト変換 | 4K化 | 計算コスト | 想定リスク |
|---|--------|--------------|------|-----------|----------|
| A | **Pillarbox** | 左右に黒帯／ぼかし | Real-ESRGAN | 低 | 視聴体験は妥協、ただし原画を毀損しない |
| B | **Crop** | 上下を切る | Real-ESRGAN | 低 | 構図破綻リスク大、頭が切れる等 |
| C | **Outpaint** | 左右をAIで生成補完 | Real-ESRGAN | 高 | 破綻リスク、時間方向の揺れ |
| D | **Hybrid（独自）** | シーン分類で A/B/C を自動切替 | Real-ESRGAN | 中〜高 | 切替境界の不自然さ |

**D が本実験のコア提案**。「キャラ顔のクローズアップ → Pillarbox」「広い風景 → Outpaint」「動きの少ない静止画 → Outpaint」など、シーンの種類で最適手法を選ぶ。

### 2-3. 使用モデル候補

| 用途 | モデル | 採用理由 | Mac MPS 対応 |
|------|--------|---------|------------|
| 4K化（アニメ特化） | **Real-ESRGAN（anime6B モデル）** | アニメ・イラスト向けに学習済み。事実上の業界標準 | ◎ |
| 4K化（代替） | RealCUGAN | より保守的な仕上がり。元絵尊重 | ◎ |
| Outpainting | **Stable Diffusion XL Inpaint + ControlNet** | 周辺コンテキストを保てる。LoRAで絵柄追従可 | ○（やや遅い） |
| シーン分類 | CLIP（ViT-B/32） | 軽量、ゼロショット分類で十分 | ◎ |
| 時間整合性 | RAFT（オプティカルフロー） | フレーム間揺れの検出に使用 | ○ |

## 3. パイプライン全体図

```
入力動画 (4:3, SD)
   │
   ├─► [1] フレーム分解 (ffmpeg)
   │
   ├─► [2] シーン分類 (CLIP)
   │      → "closeup" / "landscape" / "action" / "dialogue" のいずれかにラベリング
   │
   ├─► [3] 手法選択（Hybrid のみ）
   │      closeup → Pillarbox
   │      landscape, dialogue → Outpaint
   │      action → Crop or Pillarbox（揺れ抑制のため）
   │
   ├─► [4] アスペクト変換（手法別）
   │      A: Pillarbox  → 左右に縮小縦サイズ黒帯／背景ぼかし
   │      B: Crop       → 上下を切って 16:9
   │      C: Outpaint   → SD Inpaint で左右生成
   │
   ├─► [5] 4K アップスケール (Real-ESRGAN anime6B, x4)
   │
   ├─► [6] 時間整合性チェック（RAFT）
   │      → フレーム間ジッタが閾値超え時は前フレーム参照で再生成
   │
   └─► [7] フレーム再結合 + 音声マージ (ffmpeg)
        → 出力動画 (16:9, 4K)
```

## 4. 評価指標

| 種類 | 指標 | 計測方法 |
|------|------|---------|
| 定量 | PSNR / SSIM（vs 元動画クロップ部） | 中央領域のみで比較 |
| 定量 | LPIPS（知覚的類似度） | 学習済みLPIPSモデル |
| 定量 | 時間ジッタ量 | フレーム間 ΔSSIM の標準偏差 |
| 定性 | 5段階主観評価 | ① 不自然なし ② キャラ崩れなし ③ 全体の一貫性 |

## 7. 既知のリスクと対策

| リスク | 対策 |
|-------|------|
| Outpaint結果が原作絵柄と乖離 | 対象作品でLoRA軽量微調整（数百枚で可） |
| 時間方向のチラつき | RAFTでフロー一致を強制、または同一シードでフレーム間連続生成 |
| Mac M系でSD推論が遅い（数十秒/枚） | バッチ処理＋夜間実行、本番はクラウドGPU検討 |
| 著作権リスク | 実験段階ではPD素材のみ。商用化検討時に別途権利クリア |
